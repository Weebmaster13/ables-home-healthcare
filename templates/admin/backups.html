Production backups

Create a PostgreSQL, MySQL/MariaDB, or SQLite backup, bundle uploads, and verify the archive. Keep an off-host copy.

Backup now This dumps the configured database server — pg_dump for PostgreSQL, mysqldump for MySQL/MariaDB — bundles uploaded files, and verifies the result. On a local SQLite database it copies the SQLite file instead. If the matching dump tool is missing the backup fails loudly rather than producing a misleading file. Copy every backup off-host to durable storage — the local backups/ folder is not a real backup on its own.
Launch checklist

Backup policy before real client use

  • Create a test backup, download it, and restore it into a throwaway database to prove recovery works.
  • Automate the backup (cron) and copy each archive off-host to durable, access-controlled storage.
  • Confirm who checks backups weekly and how long old backups are kept.
  • Store uploaded documents on persistent storage, not an ephemeral container path such as /tmp.
  • Do not store backup files on a public computer or share them through personal email.
